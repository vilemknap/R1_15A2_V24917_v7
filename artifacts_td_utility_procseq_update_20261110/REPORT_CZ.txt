Umístění v obvyklém postupu:
  Trip Generation
  Run script -> R1_UPDATE_TD_UTILITIES_FROM_SKIMS.py
  Trip Distribution
  původní postprocessing včetně LONG masky a převodů 20A/20B
  assignment
  Calculate PrT skim matrix: T0 a TCur pro CW, CW_noT, CS, CS_noT, CL
Časy z posledního assignmentu jsou vstupem následující iterace. Při úplně
prvním použití musí být časové matice již spočtené. Zachovej také další
původně počítané veličiny, například DIS pro vzdálenostní diagnostiku.

Toto je pouze aktualizační krok. Vyžaduje už připravené matice 9700–9715
a jejich správné utility reference ze stávajícího jednorázového setupu.
Nepřidává ani neodstraňuje matice, nepřepojuje TD, nepíše parametry postupu,
nespouští skimy/assignment/TD, nevolá Procedures.Execute a neukládá verzi.
Je proto určen přímo do běžící Procedure Sequence, oproti dřívějšímu
ručnímu R1_STANDALONE_COMPONENT_TD_UTILITIES.py. Ten sem nevkládej.
Nekombinuj více aktualizátorů v jednom průchodu ani tuto samostatnou variantu
s již integrovanou kongesční zpětnou vazbou kalibrátoru.

Po smazání assignment výsledků nejsou uložené cesty ani DIS nutné. Musí ale
zůstat dostupné DATA matice TTC/TT0. Pokud smazání výsledků vyprázdní i je,
krok se bezpečně zastaví; uspořádej pak aktualizaci po skim výpočtu a před
mazáním výsledků pro následující TG/TD. Pouhá existence časové matice není
důkazem jejího stáří: krok ověřuje zdrojový NO/CODE/DSeg, typ, rozměry, pořadí
zón a konečné hodnoty, nikoli čas posledního nativního přepočtu. V auditu je
proto výslovně freshness_certified=false. Za výpočet T0/TCur po správném
assignmentu odpovídá konfigurace nativního postupu. Skript je nepřepočítává.
Nejde o certifikát assignment epochy nebo o akceptovaný výsledek kalibrátoru.

Výpočet zůstává shodný: cíl = M9002 * clip(TTC/TT0,1,4),
nová utility = 0.5 * předchozí + 0.5 * cíl. CW/CW_noT jsou vážené aktuálními
M9301/M9302 pro WORK a SCHOOL; CS/CS_noT přes M9303/M9304 pro SERVICE;
LONG používá CL. M9002 zůstává zachována; diagonály utility převezmou její
současné hodnoty. Pět LONG může mít stejnou korekci, stejně jako komponenty
jiných společných rodin. Parametry b/c, P/A, LONG maska, FOREIGN a akceptace
se nemění. Aktualizace nepřerozděluje ani nezapisuje žádnou poptávkovou matici.

Před zápisem se načtou a ověří všechny vstupy. Chybějící/duplicitní časy,
NaN/Inf, rozměrová chyba, neplatný typ, segment bez jediného kladného časového
páru nebo chybná reference znamenají chybu před prvním SetValues. Po zápisu
se ověří všechny utility, společný základ i stejné časové/OD zdroje. Částečně
selhané setters jsou vlastněné před voláním; rollback vrací jen vlastní
utility zápisy a ověřuje je zpětným čtením. Neověřená obnova je explicitní chyba.
Hotové skimy ani jejich zdrojové matice se při tom nezapisují.
